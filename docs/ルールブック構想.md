# ルールブック構想（運営向け IA の正）

この文書は、運営向け「ルール設定」の **中心概念とメニュー構成** を固定する。  
実装・画面文言はここに矛盾しないこと。

最終更新: 2026-08-20

関連憲章：[プロダクト完成図.md](./プロダクト完成図.md)  
Phase1 確定：[PHASE1_REDESIGN.md](./PHASE1_REDESIGN.md)

## 1. ひとことでいうと

**サービスと自治体を選ぶと、国・県・市の公式資料から下書きのルールブックが出る。人が直して確定したものが物差しになる。**  
施設が上げた書類は、書類同士の整合と、このルールブックとの整合を確認する。

チェックできる観点が増えたため、**領域で切る必要はなくした。** 根拠の置き場としての資料庫も役割を終えた。代わりに **カバー率** で、監査に必要な根拠情報を登録できているかを目視確認する。

本線:

1. **ルールブック作成** で、国／県／市の公式PDF直URLを置いて「ルール案を生成」する。参考リンク（HTML）はリンク集。抽出と監視の本文はPDFだけ  
2. 読むPDFのURLは **監視状況** に載り、中身の更新を見る  
3. 生成された **ルール下書き** で件数・参照資料数・カバー率を見て直す。一覧カードは閲覧と同じ。承認待ちだけ本文を直し、登録済みは読み取り専用。直した文は確定時に残る。確定する／全て破棄する  
4. 確定するまでチェックに使わない  
5. **ルールブック閲覧** は国・県（共通）と各市を分ける。追加・停止・削除はここ（登録済みルールの保存はしない）。問題なければ「訪問介護に戻る」で終わる。初回登録・監査観点の確認状況・頻出観点の基本確認・次にやることは出さない  
6. **根拠情報** で不足カテゴリを追加し、カバー率を上げる。修正／ルールブックへ追加ができる  
7. PDFが変わったら監視状況が知らせる → 人が原文を確認する → **作成**の該当段へ戻る  
8. 書類チェックは、書類同士＋確定済みルールブックとの整合を見る（国・県の共通＋その市）

抽出は資料（PDF）ごとに行う。1件失敗しても層全体をゼロにせず、出せた分は了承画面に残す。資料が無い層だけ、書類と見比べる標準の観点で穴埋めする。資料があるのに0件なら、了承画面に「この層は出せなかった」と出す（テンプレで成功扱いにしない）。本文が無い層は、了承画面から根拠情報へ案内する（AIにリンク修正はさせない）。

置くのは **PDFの直URL**（お知らせ一覧ではない）。HTMLの案内ページはリンク集に置く。AIがリンクを推測したり、一覧ページをPDF化したりはしない。通知のあと、**自動では本番ルールを書き換えない**。

見比べ本文の欄名は「ルール」（見出しは「ルール名」）。

合否や「指摘されないこと」は保証しない。出せるのは「指摘されやすい観点の下書き → 了承」まで。

## 2. メニュー構成（正）

トップ名称：**ルール設定**  
サイドナビは **利用設定／監視状況** の2本のみ。

施設側の主要導線（設定の外）は **運用AI監査／あとで確認／監査結果／設定**。運営者メニューからルール設定へ入る。

```
ルール設定
├─ 利用設定
│    ├─ サービス設定
│    │    ├─ 訪問介護
│    │    │    ├─ ルールブック作成
│    │    │    ├─ ルールブック閲覧
│    │    │    └─ 根拠情報
│    │    ├─ 通所介護（準備中）
│    │    └─ その他（準備中）
│    └─ マスタ管理
│         ├─ サービスマスタ
│         └─ 自治体マスタ
└─ 監視状況
```

ルール設定の作業画面:

```
ルール下書き（件数・参照資料数・カバー率・閲覧と同じ一覧カード・追加・確定／全て破棄）
ルールブック作成（国・県／市のPDF URL → ルール案を生成）
根拠情報（カバー率と根拠カテゴリ。修正／ルールブックへ追加）
```

**サマリは置かない。** 進め方カードや横断ショートカットも置かない。

国・県設定／自治体設定／根拠URL／判定ルール管理（生成→承認待ち）は本線から外す。旧URLは「ルールブック閲覧」またはマスタへリダイレクトする。領域マスタ（`/admin/rules/domains`）は利用設定へリダイレクトする。

## 3. 動線ルール（迷子防止）

1. **1画面1作業**（例：国・県の下書き／市の下書き／下書きを直して確定する／確定済みを見る／根拠情報でリンクを直す）
2. **横飛びリンク禁止**（監視状況などを別枠から飛ばさない）。例外：了承画面で本文0件のとき根拠情報へ。監視で差分ありのとき「作成」へ。監視でエラーのとき根拠情報へ
3. **次の作業は親へ戻ってから進む**（パンくずが正）
4. **説明文は必要最小限**（枠の見出し＋動詞リンクで足りる）
5. **各作業は明確な枠（カード／section）で区切る**

## 6. カバー率

- **根拠情報**：根拠カテゴリ（訪問介護・事故報告・加算届など）のうち、資料名・URLを置いた割合。同じ枠に「カバー率を上げるために以下の情報追加をご確認ください」と、カテゴリごとの資料・修正／ルールブックへ追加を出す  
- **ルール下書き**：国・県・市に読むPDFがある層の割合（参照資料数と併記）  

100%でも足りていることの保証ではない。色だけに頼らず、件数と登録済み／未登録を併記する。

領域マスタはUIから外した。内部の紐づけは残すが、作成・閲覧の選択軸にはしない。

---

## 7. 安全装置（変えないこと）

1. URLを読んだだけで本番チェック基準にしない  
2. 下書きの自動生成 ≠ 確定（人が確定するまでチェックに使わない）  
3. 旧版を消し飛ばさない  
4. 断定禁止・Wチェック支援の憲章は維持
