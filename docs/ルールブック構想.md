## 1. ひとことでいうと（ユーザーが覚えること）

**このサービス・この自治体で運営するなら、このルールブックに従えばよい。**

- ルールブックは **サービス単位** で、国＋県＋市の公開情報を束ねた「確定版の従うべき基準」
- 運営は **介護サービス選定 → 国・県 → 市区町村 → 監査カテゴリ** の順で整える
- **更新アラートは自動**で立つ
- AIが **判定ルール案＋根拠** を出し、**人が了承**したものだけが最新の確定版になる
- 書類チェックは、この確定版（の中の承認済み判定ルール）を参照する
- 施設（管理者）は、運営が **運用中** にしたサービス×自治体を選んで利用開始する（当面は訪問介護×5市・1組）

### 更新ループ（目指す動き）

```
介護サービス選定
  → 国・県ルール設定で公開情報PDF／URLを登録（サービス共通）
  → 市区町村ルール設定で市の公開情報を登録し運用／停止
  → 監査カテゴリ（4チェック）で関連PDF確認・更新情報管理・ルール了承
  →（初回）本文から判定ルール案＋根拠を生成 → ルール管理（横断）またはカテゴリ内で了承
  →（差分）更新アラート → 判定ルール案を再生成 → 了承
  → 了承済みの束＝その自治体のルールブック（チェックに使う）
```

※ URLを読んだだけで本番チェックに載せない。了承前は提案のみ。  
※ 手動管理画面はトラブル時・手動調整用。  
※ **一覧ページURLだけの登録だと、台帳には載っても「以降の変更を自動監視」までは行かないことがある。更新アラートにはPDF直リンクが必要。**

## 2. メニュー構成（目標）

トップ名称：**ルール設定**  
入口：`/admin/rules` → `/admin/rules/services`（介護サービス選定）

```
ルール設定
├─ 介護サービス選定（入口）
│    └─ [サービス]（例：訪問介護）
│         ├─ 国・県ルール設定（サービス共通の公開情報）
│         └─ 市区町村ルール設定（運用／停止）
│              └─ [市]
│                   ├─ 市の公開情報
│                   └─ 監査カテゴリ設定（現行4・将来追加可）
│                        └─ [カテゴリ]
│                             ├─ 関連PDFの確認（自動検索は今後）
│                             ├─ 【更新情報管理】
│                             └─ ルール設定（了承 → ルールブック）
├─ ルール管理（判定ルール案の生成・了承キュー・更新履歴）
├─ 公開情報台帳管理
└─ 監視トラブル（日常外）
```

**判定ルール案の生成と了承**は **ルール管理** が主導線。市・国県画面は公開情報の登録に集中し、ルール管理へ誘導する。

## 4. 安全装置（変えないこと）

1. **URLを読んだだけで本番チェック基準にしない**  
2. **台帳への反映 ≠ 判定ルールの自動反映**（人が通したものだけ）  
3. **旧版を消し飛ばさない**（いつの基準で見たか説明可能）  
4. 断定禁止・Wチェック支援の憲章は維持

---

## 5. Phase1 の範囲

- サービス：**訪問介護**（通所等は停止＝準備中）
- 自治体（市）：**横浜・川崎・藤沢・鎌倉・茅ヶ崎**（＋国・神奈川県の層）
- 施設選択：サービス×自治体は **当面1組**（複数組合せは将来）
- 国・県PDF：**サービスごとに共通**（市をまたいで共有）
- 監査カテゴリ：現行4（ケアプラン⇔計画書／計画⇔実績／シフト⇔提供記録／国保連請求⇔実績）。**将来追加可能**
- 了承：カテゴリ内の状況表示＋横断「ルール管理」（**生成の主導線もルール管理**）
- 関連PDFの自動検索→採用／不採用：国・県・市の登録済み公開情報からキーワード検索し、候補を人が採用／不採用。採用で台帳監視開始（外部サイトの新規クロールは今後）

---

## 6. 施設向けとの関係

- 施設はオンボーディング／設定で、運営が **運用中** にしたサービス×自治体から選ぶ  
- **ルールブック本体の編集・承認は運営**が行う  
- 施設はチェック結果で「このチェックで使った基準」を見る
