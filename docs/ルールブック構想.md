この文書は、運営向け「ルール設定」の **中心概念とメニュー構成** を固定する。  
実装・画面文言はここに矛盾しないこと。

最終更新: 2026-08-15

関連憲章：[プロダクト完成図.md](./プロダクト完成図.md)  
Phase1 確定：[PHASE1_REDESIGN.md](./PHASE1_REDESIGN.md)

## 1. ひとことでいうと

**サービス・領域・自治体を選ぶと、国・県・市の公式資料から下書きのルールブックが出る。人が直して確定したものが物差しになる。**  
施設が上げた書類は、書類同士の整合と、このルールブックとの整合を確認する。

本線:

1. **資料先**で、国／県／市ごとに「読むべき公式PDFの直リンク」を人が置く（領域の下には置かない）  
2. 置いたURLは **監視状況** に載り、中身の更新を見る  
3. **ルールブックを作る** は次の順。抽出は各段の「下書きを作る」1つ（領域ごとに生成ボタンは置かない）  
   ① 領域を選ぶ（チェック。全て＝運用中をまとめて。追加は領域マスタ）  
   ② 国・県の資料を確認 → 下書きを作る → 直して確定（共通ルール。全市で使う）  
   ③ 自治体を選ぶ → 市の資料を確認 → 下書きを作る → 直して確定  
4. 確定するまでチェックに使わない  
5. **ルールブックを見る** は国・県（共通）と各市を分ける。追加・修正・削除・停止はここ  
6. PDFが変わったら監視状況が知らせる → 人が原文を確認する → **作る**の該当段へ戻る  
7. 書類チェックは、書類同士＋確定済みルールブックとの整合を見る（国・県の共通＋その市）  

資料が無い層だけ、書類と見比べる標準の観点で穴埋めする。資料があるのに0件なら、了承画面に「この層は出せなかった」と出す（テンプレで成功扱いにしない）。本文が無い層は、了承画面から資料先へ案内する（AIにリンク修正はさせない）。

置くのは **PDFの直URL**（お知らせ一覧ではない）。AIがリンクを推測したり、一覧ページをPDF化したりはしない。通知のあと、**自動では本番ルールを書き換えない**。

国・県・市の画面に領域ごとの生成ボタンは置かない。抽出は「作る」の各段、根拠の住所は資料先（作るの確認枠からも置ける）。

合否や「指摘されないこと」は保証しない。出せるのは「指摘されやすい観点の下書き → 了承」まで。

**「全て」は領域マスタの1件ではない。** 運用中の領域をまとめて選ぶ仮想選択肢。

## 2. メニュー構成（正）

トップ名称：**ルール設定**  
サイドナビは **利用設定／監視状況** の2本のみ。

```
ルール設定
├─ 利用設定
│    ├─ サービス設定
│    │    ├─ 訪問介護
│    │    │    ├─ ルールブックを作る
│    │    │    ├─ ルールブックを見る
│    │    │    └─ 資料先
│    │    ├─ 通所介護（準備中）
│    │    └─ その他（準備中）
│    └─ マスタ
│         ├─ 領域マスタ
│         └─ 自治体マスタ
└─ 監視状況
```

**サマリは置かない。** 進め方カードや横断ショートカットも置かない。

国・県設定／自治体設定／根拠URL／判定ルール管理（生成→承認待ち）は本線から外す。旧URLは「ルールブックを見る」またはマスタへリダイレクトする。

## 3. 動線ルール（迷子防止）

1. **1画面1作業**（例：領域を選ぶ→国・県の下書き／市の下書き／下書きを直して確定する／確定済みを見る／資料先でリンクを直す）
2. **横飛びリンク禁止**（監視状況などを別枠から飛ばさない）。例外：了承画面で本文0件のとき資料先へ。監視で差分ありのとき「作る」へ。監視でエラーのとき資料先へ
3. **次の作業は親へ戻ってから進む**（パンくずが正）
4. **説明文は必要最小限**（枠の見出し＋動詞リンクで足りる）
5. **各作業は明確な枠（カード／section）で区切る**

## 4. 用語の正（UIに出す言葉）

| 正 | 意味 | UIに出さない |
|----|------|----------------|
| サービス設定 | 訪問介護などの一覧 | — |
| 領域マスタ | チェック領域の追加・修正・停止・削除 | カテゴリ |
| 領域 | 人員基準・勤務表・加算・減算・請求要件など | audit category |
| 全て | 運用中領域のまとめ選択（マスタ行ではない） | — |
| ルールブックを作る | 領域→国・県→市の順で下書きを出す。監視の作り直しもここ | 1件生成／全て生成（領域カード下） |
| ルールブック下書き | 確定前の一式 | ジョブ |
| 確定する | 下書きを本番の物差しにする | 一括承認 |
| ルールブックを見る | 国・県（共通）または各市の確定済み。追加・修正・削除・停止 | 判定ルール管理 |
| 資料先 | 国・県・市の公式PDF直リンクを置く／直す。登録すると監視に乗る | 根拠URL設定（本線） |
| 自治体マスタ | 管轄の対応／非対応 | ルールセット |
| ルールブック | 確定済み判定ルール一式（サービス×領域×市） | ルールセット |
| 監視状況 | 公式PDFの更新結果。差分あり→原文確認→作り直す | 監視トラブル・判定ルール案 |

内部の **ルールセット／audit_items** は画面に出さない。市名は「横浜市」のように出す。

## 6. 領域マスタ

初期領域（slug は変えない。停止は可。削除は不可）:

- 人員基準（`staffing`）
- 勤務表（`shift-table`）
- 加算・減算（`addition-reduction`）
- 請求要件（`billing`）

運営は領域の **追加・修正・停止・削除** ができる。

- 停止：新規の生成・選択から外す。既存ルールブックは残す
- 削除：初期領域以外、かつ判定ルールが紐づいていないときだけ

---

## 7. 安全装置（変えないこと）

1. URLを読んだだけで本番チェック基準にしない  
2. 下書きの自動生成 ≠ 確定（人が確定するまでチェックに使わない）  
3. 旧版を消し飛ばさない  
4. 断定禁止・Wチェック支援の憲章は維持
