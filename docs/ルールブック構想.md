# ルールブック構想（運営向け IA の正）

この文書は、運営向け「ルール設定」の **中心概念とメニュー構成** を固定する。  
実装・画面文言はここに矛盾しないこと。

最終更新: 2026-08-11

関連憲章：[プロダクト完成図.md](./プロダクト完成図.md)  
Phase1 確定：[PHASE1_REDESIGN.md](./PHASE1_REDESIGN.md)

## 1. ひとことでいうと

**このサービス・この自治体のルールブックに、どのカテゴリの判定ルールを載せるか。**

---

## 2. メニュー構成（正）

トップ名称：**ルール設定**  
サイドナビは **利用設定／監視状況** の2本のみ。

```
ルール設定
├─ 利用設定
│    └─ サービス設定
│         ├─ 訪問介護
│         │    ├─ カテゴリ設定
│         │    ├─ 国・県設定
│         │    │    └─ 根拠URL設定
│         │    └─ 自治体設定
│         │         ├─ 登録自治体
│         │         │    ├─ 根拠URL設定
│         │         │    └─ 判定ルール管理
│         │         │         ├─ 承認待ち
│         │         │         └─ 登録ルール一覧
│         │         │              └─ ルール生成（まとめてAI／個別：原文・AI・手動）
│         │         └─ 自治体マスタ
│         ├─ 通所介護（準備中）
│         └─ その他（準備中）
└─ 監視状況
```

**サマリは置かない。** 進め方カードや横断ショートカットも置かない。

---

## 3. 動線ルール（迷子防止）

1. **1画面1作業**（例：根拠URLの登録だけ／承認だけ）
2. **横飛びリンク禁止**（監視状況・判定ルール・国県などを別枠から飛ばさない）
3. **次の作業は親へ戻ってから進む**（パンくずが正）
4. **説明文は必要最小限**（枠の見出し＋動詞リンクで足りる）
5. **各作業は明確な枠（カード／section）で区切る**

---

## 4. 用語の正（UIに出す言葉）

| 正 | 意味 | UIに出さない |
|----|------|----------------|
| サービス設定 | 訪問介護などの一覧 | — |
| カテゴリ設定 | ルールブックに載せる「何を見るか」 | チェック見出し／監査項目 |
| 国・県設定 | サービス共通の根拠URL | — |
| 自治体設定 | 市の公開と市配下の作業入口 | ルールセット |
| 登録自治体 | 公開／停止する市の一覧 | — |
| 自治体マスタ | 管轄のマスタ一覧 | — |
| 根拠URL設定 | PDF等の登録・修正・削除 | 公開情報（監視詳細以外） |
| 判定ルール管理 | 承認待ちと登録済みの管理 | AI判定ルール |
| 承認待ち | 本番前の確認キュー | 了承待ち（旧） |
| 登録ルール一覧 | 利用中・登録済みのルール | — |
| 監視状況 | 根拠URLの同期結果 | 監視トラブル |

内部の **ルールセット** は画面に出さない。市名は「横浜市」のように出す。

---

## 6. 安全装置（変えないこと）

1. URLを読んだだけで本番チェック基準にしない  
2. 台帳への反映 ≠ 判定ルールの自動反映（承認が必要）  
3. 旧版を消し飛ばさない  
4. 断定禁止・Wチェック支援の憲章は維持  

---

## 7. Phase1 の範囲

- サービス：**訪問介護**（通所等は準備中）  
- 自治体：**横浜・川崎・藤沢・鎌倉・茅ヶ崎**（＋国・神奈川県）  
- 根拠の最低：国・県・市それぞれ PDF 1件以上で公開可  
- カテゴリ：初回は標準カテゴリセットで可
