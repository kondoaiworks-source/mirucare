# ルールブック構想（運営向け IA の正）

この文書は、運営向け「ルール設定」の **中心概念とメニュー構成** を固定する。  
実装・画面文言はここに矛盾しないこと。

最終更新: 2026-08-09

関連憲章：[プロダクト完成図.md](./プロダクト完成図.md)  
Phase1 確定：[PHASE1_REDESIGN.md](./PHASE1_REDESIGN.md)

---

## 1. ひとことでいうと

**このサービス・この自治体で運営するなら、この判定ルールに従えばよい。**

進め方（必ずこの順で説明する）:

1. **サービス**を選ぶ  
2. **対象自治体**を整える（公開／停止）  
3. **根拠URL**を登録する（国・県・市のPDF）  
4. **チェック見出し**を用意する（初回：標準見出しセット）  
5. **判定ルール**を整える（了承待ち → 一覧 → ルール案を生成）  
6. **監視状況**で根拠URLの同期エラーを見る  

- AI／手動で **ルール案** を出し、**了承**したものだけがチェックに使われる  
- 施設は、運営が **公開中** にしたサービス×自治体だけを選べる

## 2. 用語の正（UIに出す言葉）

| 正 | 意味 | UIに出さない |
|----|------|----------------|
| サービス | 訪問介護など | — |
| 対象自治体 | 公開する市 | ルールセット |
| 根拠URL | 国・県・市の参照PDF等 | 公開情報（監視詳細以外） |
| チェック見出し | 何を見るかの項目 | 監査項目（詳細ページのみ併記可） |
| 標準見出しセット | 訪問介護のひな形一括 | 訪問介護テンプレート |
| 判定ルール | どう疑うかの本文 | AI判定ルール |
| ルール案を生成 | AI／手動で案を作る | — |
| 了承 | 案を本番に載せる | — |
| 監視状況 | 根拠URLの同期結果 | 監視トラブル |

**ルールセット**は内部（DB）用語。画面では「横浜市（訪問介護）」のように出す。

## 3. メニュー構成

トップ名称：**ルール設定**  
入口：`/admin/rules` → `/admin/rules/setup`（利用設定）

```
ルール設定
├─ 利用設定
│    ├─ ① サービス
│    ├─ ②③ 対象自治体・根拠URL（国・県／市）
│    ├─ ④ チェック見出し（初回）
│    └─ ⑤ 判定ルール
│         ├─ 了承待ちの判定ルール案
│         ├─ ルール一覧
│         └─ ルール案を生成 → 手動で追加（別ページ）
└─ 監視状況
     └─ エラー詳細（根拠URLの再確認へ）
```

市画面は **根拠URLの登録に集中**。生成・了承は判定ルールへ誘導する。

## 4. 画面対応

| 構想上の名前 | 場所 |
|--------------|------|
| 利用設定 | `/admin/rules/setup` |
| サービス詳細 | `/admin/rules/services/[service]` |
| 国・県の根拠URL | `.../national-prefecture` |
| 対象自治体 | `.../municipalities` |
| 市の根拠URL | `.../municipalities/[city]` |
| チェック見出し | `/admin/rules/audit-items` |
| 判定ルール | `/admin/rules/pending` |
| 手動で追加 | `/admin/rules/manual` |
| 監視状況 | `/admin/rules/monitoring` |

---

## 5. 安全装置（変えないこと）

1. URLを読んだだけで本番チェック基準にしない  
2. 台帳への反映 ≠ 判定ルールの自動反映（了承が必要）  
3. 旧版を消し飛ばさない  
4. 断定禁止・Wチェック支援の憲章は維持  

---

## 6. Phase1 の範囲

- サービス：**訪問介護**（通所等は停止＝準備中）  
- 自治体：**横浜・川崎・藤沢・鎌倉・茅ヶ崎**（＋国・神奈川県）  
- 根拠の最低：国・県・市それぞれ PDF 1件以上で公開可  
- チェック見出し：初回は標準見出しセットで可
