# ルールブック構想（運営向け IA の正）

この文書は、運営向け「ルール設定」の **中心概念とメニュー構成** を固定する。  
実装・画面文言はここに矛盾しないこと。

最終更新: 2026-08-14

関連憲章：[プロダクト完成図.md](./プロダクト完成図.md)  
Phase1 確定：[PHASE1_REDESIGN.md](./PHASE1_REDESIGN.md)

## 1. ひとことでいうと

**サービス・領域・自治体を選ぶと下書きのルールブックが出る。人が直して確定したものが物差しになる。**  
施設が上げた書類は、書類同士の整合と、このルールブックとの整合を確認する。

本線:

1. 介護サービスと領域と対象自治体を選ぶ  
2. 下書きのルールブックが自動で出る（国・県の標準観点 ＋ その市のPDFから市固有ルール）。市固有が足りなければ下書き画面で「市の資料からルールを出す」  
3. 人が **修正・追加・削除** して **確定** する  
4. 確定後は **ルールブックを見る** で一覧・修正・追加・停止・削除と、確認した資料先を見る  
5. 書類チェックは、書類同士＋確定済みルールブックとの整合を見る  

人が国・県・市ごとにPDFを登録してからルールを生成・承認する作業は、本線にしない。

**「全て」は領域マスタの1件ではない。** 運用中の領域をまとめて選ぶ仮想選択肢。

## 2. メニュー構成（正）

トップ名称：**ルール設定**  
サイドナビは **利用設定／監視状況** の2本のみ。

```
ルール設定
├─ 利用設定
│    ├─ サービス設定
│    │    ├─ 訪問介護
│    │    │    ├─ ルールブックを作る
│    │    │    └─ ルールブックを見る
│    │    ├─ 通所介護（準備中）
│    │    └─ その他（準備中）
│    ├─ 領域マスタ
│    └─ 自治体マスタ
└─ 監視状況
```

**サマリは置かない。** 進め方カードや横断ショートカットも置かない。

国・県設定／自治体設定／根拠URL／判定ルール管理（生成→承認待ち）は本線から外す。旧URLは「ルールブックを見る」またはマスタへリダイレクトする。

---

## 3. 動線ルール（迷子防止）

1. **1画面1作業**（例：3つ選んで下書きを作る／下書きを直して確定する／確定済みを見る）
2. **横飛びリンク禁止**（監視状況などを別枠から飛ばさない）
3. **次の作業は親へ戻ってから進む**（パンくずが正）
4. **説明文は必要最小限**（枠の見出し＋動詞リンクで足りる）
5. **各作業は明確な枠（カード／section）で区切る**

## 4. 用語の正（UIに出す言葉）

| 正 | 意味 | UIに出さない |
|----|------|----------------|
| サービス設定 | 訪問介護などの一覧 | — |
| 領域マスタ | チェック領域の追加・修正・停止・削除 | カテゴリ |
| 領域 | 人員基準・勤務表・加算・減算・請求要件など | audit category |
| 全て | 運用中領域のまとめ選択（マスタ行ではない） | — |
| ルールブックを作る | 3軸から下書きを出す入口 | ルールセット |
| ルールブック下書き | 確定前の一式 | ジョブ |
| 確定する | 下書きを本番の物差しにする | 一括承認 |
| ルールブックを見る | 確定済みの一覧・修正・追加・停止・削除と資料先 | 判定ルール管理 |
| 資料先 | ルール作成時に確認した公式PDF／ページ | 根拠URL設定（本線） |
| 自治体マスタ | 管轄の対応／非対応 | ルールセット |
| ルールブック | 確定済み判定ルール一式（サービス×領域×市） | ルールセット |
| 監視状況 | 公式資料の同期結果（裏方） | 監視トラブル |

内部の **ルールセット／audit_items** は画面に出さない。市名は「横浜市」のように出す。

## 5. 画面対応

| 構想上の名前 | 場所 |
|--------------|------|
| 利用設定 | `/admin/rules/setup` |
| 領域マスタ | `/admin/rules/domains` |
| 自治体マスタ | `/admin/rules/municipalities` |
| サービス（訪問介護） | `/admin/rules/services/homecare` |
| ルールブックを作る | `.../compose` |
| ルールブック下書き | `.../compose/[jobId]` |
| ルールブックを見る | `.../book`（`?city=` で自治体） |

旧「国・県設定」「自治体設定」「判定ルール管理」URLは `.../book` または自治体マスタへリダイレクトする。

チェック時の足し方：**国・県の共通ルール ＋ その市のルール**（例：横浜＝共通＋横浜市）。

| 監視状況 | `/admin/rules/monitoring` |

旧「カテゴリ設定」（`/admin/rules/audit-items`）は訪問介護ハブへリダイレクトする。

## 6. 領域マスタ

初期領域（slug は変えない。停止は可。削除は不可）:

- 人員基準（`staffing`）
- 勤務表（`shift-table`）
- 加算・減算（`addition-reduction`）
- 請求要件（`billing`）

運営は領域の **追加・修正・停止・削除** ができる。

- 停止：新規の生成・選択から外す。既存ルールブックは残す
- 削除：初期領域以外、かつ判定ルールが紐づいていないときだけ

---

## 7. 安全装置（変えないこと）

1. URLを読んだだけで本番チェック基準にしない  
2. 下書きの自動生成 ≠ 確定（人が確定するまでチェックに使わない）  
3. 旧版を消し飛ばさない  
4. 断定禁止・Wチェック支援の憲章は維持  

---

## 8. Phase1 の範囲

- 領域：上記4つ（＋全て）。追加は領域マスタから
