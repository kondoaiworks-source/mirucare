## 1. ひとことでいうと（ユーザーが覚えること）

**この自治体でサービスを運営するなら、このルールブックに従えばよい。**

- ルールブックは **国＋県＋市** の公開情報を束ねた「確定版の従うべき基準」
- **更新アラートは自動**で立つ
- AIが **判定ルール案＋根拠** を出し、**人が了承**したものだけが最新の確定版になる
- 書類チェックは、この確定版（の中の承認済み判定ルール）を参照する

似た登録画面（参照URL・行政資料・法令・AI判定ルール等）は **裏側の部品** であり、表の物語は「ルールブック」1本に揃える。

### 更新ループ（目指す動き）

```
参照URLを市ルールブックの「自治体ルール設定」で登録（国・県・市。PDF直リンクがあると行政資料台帳へ自動登録・監視開始）
  →（初回）本文から判定ルール案＋根拠を生成 → 新ルール判定通知で了承
  →（差分）更新アラート → 判定ルール案を再生成 → 新ルール判定通知で了承
  → 了承済みの束＝その自治体のルールブック（チェックに使う）
```

※ URLを読んだだけで本番チェックに載せない。了承前は提案のみ。  
※ 行政資料画面はトラブル時・手動調整用（日常は自治体ルール設定で足りる）。  
※ **一覧ページURLだけの登録だと、台帳には載っても「以降の変更を自動監視」までは行かないことがある。更新アラートにはPDF直リンクが必要。**
※ `/admin/rules/source-urls` は横断確認用。日常の追加・修正・削除は市ルールブック側。

## 2. メニュー構成（目標）

トップ名称：**ルール設定**（旧：チェック設定）  
入口：`/admin/rules`（URLは互換のため当面維持）

```
ルール設定
├─ ルールブック設定（入口・市一覧・確定版）
│    ├─ 新ルール判定通知
│    ├─ 更新履歴
│    └─ 自治体ルール変更通知
├─ 自治体管理
│    └─ 自治体マスタ
└─ 監視トラブル（行政資料台帳・同期の結果・日常外）
```

**入口**：`/admin/rules` は **ルールブック設定**（`/admin/rules/regulatory`）へリダイレクト。旧ホームは廃止。

**監視トラブル**（日常メニュー外）: 行政資料台帳・同期の結果のみ。  
判定ルールの追加・了承は **市ルールブック** と **新ルール判定通知**。  
監査項目テンプレ／Phase1判定ルールはルールブック設定の **初回セットアップ**。  
参照URL／更新アラート確認は **ルールブック設定**側（参照URLの日常操作は市画面の自治体ルール設定。法令・根拠画面は主導線から外す）。ハブのリンク見出しは **更新アラート管理**。

## 3. いまの画面との対応（移行マップ）

| 構想上の名前 | いま開く場所 | 状態 |
|--------------|--------------|------|
| ルール設定入口 | `/admin/rules` → `/admin/rules/regulatory` | **ホーム廃止**。ルールブック設定へリダイレクト |
| ルールブック設定 | `/admin/rules/regulatory` | ハブ。市一覧・**更新アラート管理**へ |
| 参照URL（日常） | `/admin/rules/regulatory/[slug]` の自治体ルール設定 | **正**。国・県・市の追加・修正・削除 |
| 参照URL（横断） | `/admin/rules/source-urls` | トラブル時・横断一覧。主導線からは外す |
| 法令・根拠 | `/admin/rules/laws` | 任意・旧画面。主導線からは外す |
| 自治体別の閲覧・修正 | `/admin/rules/regulatory/[slug]` | **実装済**。了承済み判定ルール、目次、更新アラート、参照URL CRUD、判定ルール案生成 |
| 判定ルール案の生成 | 市画面／差分承認 → 新ルール判定通知 | **実装済**。差分または資料本文からAIが案＋根拠。了承までチェックに載せない |
| 市でのチェック適用 | 書類チェック時 | **実装済**。他市専用ルールを除外し、国・県・自市・共通を適用 |
| 初期設定・サービス選択 | ルールブック設定ハブ／市画面 | **実装済**（訪問介護のみ選択可。他は準備中表示） |
| 新ルール判定通知 | `/admin/rules/pending` | 既存（判定ルール版）。自治体ルールからAIが生成したチェックルールを確認して反映 |
| マニュアル差分の承認 | `/admin/document-changes` | 既存。更新アラートの一環 |
| 更新履歴 | `/admin/rules/history` | 既存 |
| 自治体マスタ | `/admin/rules/municipalities` | 既存。ナビに昇格 |
| 自治体ルール変更通知 | `/admin/rules/notifications` | 既存。自治体ルール変更の感知と差分承認依頼の通知 |
| 同期の結果 | `/admin/rules/jobs` | **監視トラブル**内。自動取得の成功／失敗 |
| 行政資料（台帳） | `/admin/rules/documents` | **監視トラブル**内。日常は自治体ルール設定の参照URLで自動 |
| 監査項目／AI判定ルール | 初回セットアップ／市画面・一覧 | 主導線はルールブック。`/admin/rules/ai-rules` は一覧のみ |

## 4. 安全装置（変えないこと）

1. **URLを読んだだけで本番チェック基準にしない**  
2. **台帳への反映 ≠ 判定ルールの自動反映**（人が通したものだけ）  
3. **旧版を消し飛ばさない**（いつの基準で見たか説明可能）  
4. 断定禁止・Wチェック支援の憲章は維持

## 5. Phase1 の範囲

- サービス：**訪問介護**（通所等はプレースホルダ可）
- 自治体（市）：**横浜・川崎・藤沢・鎌倉・茅ヶ崎**（＋国・神奈川県の層）
- 市ごとの閲覧・修正：`/admin/rules/regulatory/{slug}`（実装済）
- 市画面での更新アラート確認・台帳反映、参照URL／行政資料の `?city=` 絞り込み（実装済）
- サービス選択UI：訪問介護固定（実装済）。通所等は準備中表示
- 市画面での参照URLインライン追加・編集・削除・確認済み化（国・県・市。実装済）
- 国→県→市の確定版目次（合成ビュー）（実装済）
- 差分／行政資料本文から判定ルール案＋根拠を生成し、新ルール判定通知で了承（実装済）
- 市ルールブック画面に了承済み判定ルール（チェック用中身）を表示（実装済）
- チェック時に他市専用ルールを除外し、国・県・自市・共通を適用（実装済）

## 6. 施設向けとの関係

- 施設の **設定画面の事業所情報**で所属自治体などを確認する（編集は運営のルール設定と別レイヤ）  
- **ルールブック本体の編集・承認は運営**が行う  
- 施設はチェック結果で「このチェックで使った基準」を見る
