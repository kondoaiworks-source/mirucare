# ルール設定（旧：チェック設定）かんたん操作マニュアル

**公式ポジション：**  
**「返還・合否は保証しないが、実務上の致命傷を未然に浮かび上がらせる予防装置」**

対象：ルール設定を初めて触る方（サービス運営担当など）  
開き方：**設定 → ルール設定を開く**（画面 `/admin/rules`）  
メニュー構成の正：[ルールブック構想.md](./ルールブック構想.md)

> **本サービスはWチェック支援です。**  
> 合否判定や返還リスクの保証は行いません。最終判断・行政への提出は貴施設の責任で行ってください。  
> プロダクト全体の完成図は [プロダクト完成図.md](./プロダクト完成図.md) を参照してください。

## 1. ひとことでいうと？

ルール設定は、**「この自治体ならこのルールブック」** を最新に保つ場所です。

現場の皆さんが日々行うのは「書類をアップロードしてチェックする」ことですが、  
そのチェックが **何を・どう疑うか** は、ルールブック（人が承認した確定版）に従います。

| 現場の日常 | この画面での準備 |
|------------|------------------|
| 書類を上げて指摘を見る | ルールブックの根拠と判定ルールを用意する |
| 「なぜこの指摘？」と思う | 承認済みの見方と行政資料のタイトルを確認する |
| 法改正後に不安になる | 更新アラートを人が確認してルールブックを更新する |

画面上部の **「準備の進み具合」** を見れば、「次に何をすればよいか」が分かります。

## 2. メニューはこれだけ覚えればOK

左のメニューは、**ルールブック中心** にしています。

### ルールブック

| メニュー | やること |
|----------|----------|
| **ルールブック設定** | 国・県・市の参照URL／行政資料を整え、**Phase1市のルールブック**を開く（目次・更新アラート・参照URLの追加／修正） |

### 確認する

| メニュー | やること |
|----------|----------|
| **新ルール判定通知** | 自治体ルールからAIが生成したチェックルールを確認して反映 |
| **更新履歴** | いつの版に変わったかを見る |

### 運用

| メニュー | やること |
|----------|----------|
| **自治体マスタ** | Phase1市などの対応設定 |
| **自治体ルール変更通知** | 自治体ルールの変更を感知して差分承認の依頼を通知 |
| **運用監視** | 同期・監視の実行状況 |

### 詳細設定

監査項目・判定ルール・加算など、**ルールブックの中身の部品**です。普段はルールブック設定と新ルール判定通知で足ります。

```
【ルールブック設定】
  参照URL・行政資料（国／県／市）
         ↓ 更新アラート
    人が確認して台帳へ反映
         ↓（必要なら）
    判定ルールを改訂 → 新ルール判定通知
         ↓
    書類チェックで参照
         ↓
  「気になる点」→ 人が最終確認
```

> 台帳への反映だけではチェック基準は変わりません。判定ルールの承認が別途必要です。

AIは勝手に「違反」と決めません。  
**登録・承認された項目とルールを手がかりに、「確認した方がよい可能性」を出します。**

## 3. ホーム画面の見かた

画面を開くと、だいたい次の順で並びます。

### ① 準備の進み具合（いちばん重要）

| 表示 | 意味 |
|------|------|
| **未設定** | 必須がほとんど未着手 |
| **準備中** | 必須の途中 |
| **利用可能** | 必須が揃い、確認待ちも片付いている |
| 必須 ○ / 4 | 必須ステップの完了数 |
| 任意 ○ / 2 | 加算・行政情報など（なくても始められる） |
| **次にやること** | いま押すべきボタン |

迷ったら、まず **「次にやること」** を押してください。

### ② よく使う設定（3つのカード）

| カード | 行く先 |
|--------|--------|
| 監査項目 | 項目の登録・編集 |
| AI判定ルール | 判定基準の登録 |
| 行政情報 | マニュアル・参照サイト |

### ③ いまの件数

監査項目数・承認済みルール数・新ルール判定通知などが大きい数字で出ます。  
タップすると該当画面へ進めます。

## 4. 初めての設定：この順番で

ホームの「次にやること」に従っても、下の手順でも結果は同じです。

### 必須① 対応自治体を用意する

**なぜ必要か**  
どの地域のルールで整理するかを決めるためです。

**操作**

1. **その他の設定** → **自治体マスタ**
2. チェック対象の市区町村が「対応中」になっているか確認する

（運営側ですでに入っていることが多いです）

**完了の目安**  
対応中の市区町村が **1件以上**

---

### 必須② 監査項目を登録する

**なぜ必要か**  
「何を確認したいか」の見出しがないと、AIルールの土台がありません。

**操作**

1. 左メニュー **監査項目** を開く
2. ルールセットを選ぶ（訪問介護など）
3. 項目を1件以上登録する  
   - 個別登録でもよい  
   - 訪問介護なら **「訪問介護テンプレートを登録する」** でまとめて入れられる

**完了の目安**  
監査項目が **1件以上**

---

### 必須③ AI判定ルールを登録して承認する

**なぜ必要か**  
書類チェックで使う「どう疑うか」の基準は、**承認済み**のものだけが使われます。

**操作（登録）**

1. 左メニュー **AI判定ルール** を開く
2. 紐づける監査項目・対象書類・ガイダンス（見方の説明）などを入力する
3. 「新ルール判定通知」向けに登録する（下書きの場合は、あとで了承依頼）

**操作（承認）**

1. 左メニュー **新ルール判定通知** を開く
2. 内容を確認し、確認記録を書いて **承認** する

> 「登録しただけ」では未完了です。必ず **承認** まで行ってください。

**完了の目安**  
**承認済み** のAI判定ルール版が **1件以上**

---

### 必須④ 確認待ちを残さない

**なぜ必要か**  
新ルール判定通知や行政資料の差分、同期アラートが残っていると、  
「いま有効な基準」が分かりにくくなります。

**操作**

| 表示 | 行く場所 | やること |
|------|----------|----------|
| 新ルール判定通知 | **新ルール判定通知** | 了承または差し戻し |
| マニュアル差分 | **その他の設定** → マニュアル変更の承認 | 差分を確認して台帳へ反映／却下 |
| 同期アラート | **その他の設定** → ジョブ監視 | 取得失敗などの原因を確認 |

**完了の目安**  
上記がすべて **0件**

---

### 必須が終わると

ホームの状態が **「利用可能」** になります。  
＝ **日常の書類チェックを回し始めてよい状態** です。  
＝ 今後の法改正対応まで全部終わった、という意味ではありません。

## 5. 「利用可能」の意味（大事）

「利用可能」＝ **合否や返還を保証する状態ではありません。**

致命傷になりやすい矛盾・疑義の洗い出しを始められる、**最低限の準備が整った状態**です。

- 未投入・未照合のデータは **未検証** です  
- 出ていない指摘＝問題なし、ではありません  
- 最終判断・提出は貴施設の責任です  

ホームに出る説明のイメージ：

> 最低限の設定が整い、致命傷になりやすい矛盾・疑義の洗い出しを始められます（合否・返還は保証しません）。未投入の範囲は未検証です。法改正時は行政情報の更新をご確認ください。

## 6. 任意設定（余裕があるとき）

必須が終わったあと、または並行して進めます。なくても「利用可能」にはなれます。

### 任意A. 加算項目を整える

加算は算定条件と必要書類の抜けが指摘されやすい領域です。

1. **その他の設定** → **加算設定**
2. 加算カテゴリの項目を登録・編集する

**完了の目安**  
加算項目が1件以上（未登録でも必須の「利用可能」には影響しません）

---

### 任意B. 行政情報を用意する

指摘の根拠を原文で辿れるようにするため、また法改正時の更新の起点にするためです。

1. 左メニュー **行政情報** を開く
2. 必要に応じて次を整える

| 管理一覧 | 内容 |
|----------|------|
| **行政資料** | 行政マニュアルのPDFや監視設定 |
| **参照サイト** | 自治体・厚労省などの原文URL |
| **法令・根拠** | 法令・通知などのメタ情報 |

**完了の目安**  
行政資料または参照サイトが **1件以上**

---

### 行政マニュアルの変更を反映するとき（2段階）

監視で差分が見つかった場合の流れです。

1. **その他の設定** → **マニュアル変更の承認**  
   → 問題なければ **台帳へ反映**（ここまでが第1段階）
2. チェック用の見方を変える必要があるときだけ  
   → **判定ルール案を生成する** → **新ルール判定通知**で了承（第2段階）

> **台帳への承認 ≠ AIルールへの自動反映** です。  
> 勝手にチェック基準が書き換わらないための安全装置です。

---

## 7. 日常の使い方（設定が終わったあと）

1. 現場はいつもどおり **書類チェック** や **月末の確認** を使う  
2. 法改正・集団指導のあと → **行政情報** を更新する  
3. 判定の見方を変えるとき → **AI判定ルール** → **新ルール判定通知**  
4. 「いつの基準で見た？」を確認したいとき  
   - チェック結果の **「このチェックで使った基準」**  
   - メニューの **更新履歴**  
5. トラブルや加算など、普段使わないもの → **その他の設定**

## 8. よくあるつまずき

**Q. ルールを登録したのに「利用可能」にならない**  
A. **了承**まで終わっていますか。新ルール判定通知が残っていると必須の「確認待ちを残さない」も未完了になります。

**Q. メニューが少ない／加算やジョブが見当たらない**  
A. 壊れていません。日常で迷わないよう、よく使う3つ以外は **その他の設定** に移しています。

**Q. 必須は全部完了なのに、まだやることがあるように見える**  
A. 任意（加算・行政情報）が残っていると「次にやること」に任意が出ます。必須だけ見たい場合は、状態ラベルが「利用可能」かを確認してください。

**Q. 監査項目とAI判定ルールの違いは？**  
A. 監査項目＝「何を見るか」の見出し。AI判定ルール＝「どう見るか」の具体的な基準。両方そろって初めて安定します。

**Q. 行政資料と参照サイトの違いは？**  
A. 行政資料はPDFや自動監視の台帳。参照サイトは「どの公式URLを根拠にするか」の一覧です。まずは参照サイトだけでも構いません。

**Q. 設定を間違えたら現場のチェックが危険ですか？**  
A. 本サービスはWチェック支援であり、断定や合否保証はしません。それでも誤ったルールは混乱の元なので、変更は承認フローを通してください。

**Q. 誰がこの画面を使えますか？**  
A. 原則として **運営（サービス提供側のオペレータ）** 向けです。一般の事業所スタッフの日常画面とは分かれています。

## 9. 用語のやさしい説明

| 用語 | やさしい意味 |
|------|----------------|
| チェック設定／ルール設定 | ルールブックを最新に保つ運営画面一式 |
| ルールブック | 「この自治体ならこれに従う」確定版の束 |
| 準備の進み具合 | 設定の完了度メーター |
| 必須 / 任意 | 始めに必要／あると精度が上がる |
| 利用可能 | 最低限そろって運用開始できる状態（保証ではない） |
| 監査項目 | 確認したいことの見出し（詳細設定） |
| 判定ルール | 見出しに対する具体的な見方（詳細設定・要承認） |
| 新ルール判定通知 | 本番反映前の確認キュー（チェックルール案） |
| 自治体ルール変更通知 | 自治体ルール変更の差分承認依頼 |
| ルールブック設定 | 参照URL・行政資料など根拠の入口 |
| 行政資料 | マニュアルPDFなどの台帳 |
| 参照URL | 公式ページのURL一覧 |
| 更新アラート | 監視差分・同期の要確認 |
| 詳細設定 | ルールブックの中身の部品 |
| Wチェック支援 | 最終判断は人・施設が行う前提の補助 |
