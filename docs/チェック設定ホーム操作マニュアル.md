# チェック設定ホーム 操作マニュアル

**公式ポジション：**  
**「返還・合否は保証しないが、実務上の致命傷を未然に浮かび上がらせる予防装置」**

対象：チェック設定を初めて触る方（施設の事務・管理者、サービス運営担当など）  
画面：設定 → **チェック設定を開く**（または `/admin/rules`）

> **本サービスはWチェック支援です。**  
> 合否判定や返還リスクの保証は行いません。最終判断・行政への提出は貴施設の責任で行ってください。  
> プロダクト全体の完成図は [プロダクト完成図.md](./プロダクト完成図.md) を参照してください。

## 1. この画面は何のため？

チェック設定ホームは、AIが書類をチェックするときの **「ものさし」を整える場所** です。

現場の皆さんが日々行うのは「書類をアップロードしてチェックする」ことですが、  
そのチェックが **何を・どの自治体の基準で・どこまで疑うか** は、この画面で事前に決めておきます。

| 現場の作業 | チェック設定での作業 |
|------------|----------------------|
| 書類を上げて指摘を見る | 指摘の根拠・項目・ルールを用意する |
| 「これは何の指摘？」と感じる | 監査項目・AIルール・行政資料を整える |
| 法改正後に不安になる | 行政情報・参照サイトを更新する |

**一言でいうと：**  
ホームは「設定が足りているか／次に何をすればよいか」を教えてくれる **準備状況のダッシュボード** です。

## 2. 全体の仕組み（図で理解する）

```
【行政・法令の情報】        【貴施設の運用】
  行政資料・法令・URL   →   監査項目・加算項目
           ↓                        ↓
           └────→ AI判定ルール ←────┘
                      ↓
              書類アップロード
                      ↓
              「気になる点」の指摘
                      ↓
              人が最終確認・提出
```

### 部品の役割

| 部品 | 役割 | たとえ |
|------|------|--------|
| **対応自治体** | 「どの地域のルールで見るか」 | 地図の範囲 |
| **監査項目** | 「何を確認したいか」の見出し | チェックリストの行 |
| **加算設定** | 加算の算定・書類の観点 | チェックリストの加算パート |
| **AI判定ルール** | 「どう疑うか」の具体的な見方 | 各行の採点基準 |
| **行政資料・法令・参照サイト** | 根拠の原文 | 教科書・公式ページ |
| **承認待ち** | ルール変更を本番に載せる前の確認 | 「この改訂でよいか」の印 |

AIは勝手に「違反」と決めません。  
**登録された項目とルールを手がかりに、「確認した方がよい可能性」を出します。**

## 3. なぜ設定が必要なのか

### 3-1. 設定しないとどうなるか

| 状態 | 起こりうること |
|------|----------------|
| 自治体がない | 地域の運用に合わせた整理がしにくい |
| 監査項目がない | 「何を見るか」が空なので、チェックの土台が弱い |
| AIルールが未承認 | 判定基準が本番に載らず、意図した指摘が安定しない |
| 承認待ち・差分が残る | 古い基準と新しい基準が混ざる可能性がある |
| 行政情報がない | 根拠の確認や法改正追従がしづらい（任意だが推奨） |

### 3-2. なぜ「必須」と「任意」があるのか

- **必須** … 最低限、チェックの仕組みを回すために必要  
- **任意** … なくても始められるが、加算や根拠の精度が上がる  

ホームでは必須がすべて完了すると **「利用可能」** と表示されます。  
これは「完璧に終わった」ではなく、**「ひとまず運用を始められる状態」** という意味です。

### 3-3. なぜ承認が必要か

AI判定ルールは、誤った基準がそのまま現場に流れると影響が大きいため、  
**登録 → 承認待ち → 承認** の流れにしています。

「人が一度目を通してから使う」ための安全装置です。

## 4. ホーム画面の見かた

画面を開くと、上から次の順で並びます。

### ① 準備の進み具合（いちばん重要）

| 表示 | 意味 |
|------|------|
| **未設定** | 必須がほとんど未着手 |
| **準備中** | 必須の途中 |
| **利用可能** | 必須が揃い、確認待ちも片付いている |
| 必須 ○ / 4 | 必須ステップの完了数 |
| 任意 ○ / 2 | 任意ステップの完了数 |
| **次にやること** | いま押すべきボタンはこれ1つ |

迷ったら **「次にやること」のボタンだけ** 押してください。

### ② 確認が必要なことがあります

次が出ているときは、先に片づけます。

- ルール承認待ち  
- マニュアル差分  
- 同期アラート  

### ③ 目的から選ぶ

やりたいことから入ります。

| カード | 向いている場面 |
|--------|----------------|
| 監査対策 | 運営指導で見られる項目を整えたい |
| 加算設定 | 加算の算定・書類を整えたい |
| AI設定 | 判定の基準を変えたい・精度を上げたい |
| 法改正・行政情報 | 法令改正や行政サイトの更新に対応したい |

各カードに **設定あり / 未完了** などのバッジが付きます。

### ④ 件数の詳細

件数の内訳です。進捗の判断は①を優先してください。

## 5. 初めての設定：必須4ステップ

順番どおりに進めるのがおすすめです。  
（ホームの「次にやること」も、この順で案内します）

---

### ステップ1. 対応自治体を用意する（必須）

**なぜ必要か**  
運営指導の見方は自治体によって違うことがあります。「どの地域向けか」を決めておくためです。

**操作**

1. ホーム → 「自治体マスタを開く」（または左メニュー「自治体マスタ」）
2. 一覧から対象の市区町村を確認する
3. 必要なら「対応する」状態にする（画面の案内に従う）

**完了の目安**  
対応中の市区町村が **1件以上**

---

### ステップ2. 監査項目を登録する（必須）

**なぜ必要か**  
AIや人が「何を確認するか」の見出しです。  
例：契約書の署名、計画の同意日、記録の日付、人員配置（常勤換算＝職員の人数の数え方）など。

**操作**

1. ホーム → 「監査対策を開く」
2. 画面上部の「この画面で行うこと」「操作手順」を読む
3. ルールセット（自治体×サービス）を選ぶ
4. コード・タイトル・説明・カテゴリ・リスクなどを入力して登録する

**完了の目安**  
監査項目が **1件以上**

> 最初は「よく指摘される項目」を少数でもよいので登録し、あとから増やしてください。

---

### ステップ3. AI判定ルールを承認する（必須）

**なぜ必要か**  
監査項目だけでは「見出し」だけです。  
AI判定ルールは、その項目について **書類のどこをどう見るか** を決めます。

**操作（登録）**

1. ホーム → 「AI設定を開く」→ 「AI判定ルール」
2. 紐づける監査項目・対象書類・ガイダンス（見方の説明）などを入力
3. 「承認待ち」として登録する（下書きの場合は、あとで承認依頼）

**操作（承認）**

1. 左メニュー「承認待ち」を開く
2. 内容を確認し、承認理由を書いて承認する

**完了の目安**  
**承認済み** のAI判定ルール版が **1件以上**

> 「登録しただけ」では未完了です。必ず **承認** まで行ってください。

---

### ステップ4. 確認待ちを残さない（必須）

**なぜ必要か**  
承認待ちや行政資料の差分、同期アラートが残っていると、  
「いま有効な基準」が分かりにくくなります。

**操作**

| 表示 | 行く場所 | やること |
|------|----------|----------|
| ルール承認待ち | 承認待ち | 承認または差し戻し |
| マニュアル差分 | マニュアル変更の承認 | 差分を確認して承認／却下 |
| 同期アラート | ジョブ監視 → 必要なら行政資料 | 取得失敗などの原因を確認 |

**完了の目安**  
上記がすべて **0件**

---

### 必須が終わると

ホームの状態が **「利用可能」** になります。

文言の意味：

> 最低限のチェック設定は整いました。法改正時は行政情報の更新をご確認ください。

＝ **日常の書類チェックを回し始めてよい状態** です。  
＝ 今後の法改正対応まで終わった、という意味ではありません。

## 6. 任意設定（精度を上げたいとき）

必須が終わったあと、または並行して進めます。

---

### 任意A. 加算項目を整える

**なぜあるとよいか**  
加算は算定条件と必要書類の抜けが指摘されやすい領域です。専用に整理しておくと確認しやすいです。

**操作**

1. 「加算設定」を開く  
2. 加算カテゴリの項目を登録・編集する  

**完了の目安**  
加算カテゴリの項目が **1件以上**（未登録でも必須の「利用可能」には影響しません）

---

### 任意B. 行政情報を用意する

**なぜあるとよいか**  
指摘の根拠を原文で辿れるようにするため、また法改正時の更新の起点にするためです。

**操作（法改正・行政情報から）**

| 管理一覧 | 内容 |
|----------|------|
| **行政資料** | 行政マニュアルのPDFや監視設定 |
| **法令・根拠** | 法令・通知などのメタ情報 |
| **参照サイト** | 自治体・厚労省などの原文URL |

**完了の目安**  
行政資料または参照サイトが **1件以上**

## 7. 目的別メニューの使い分け

「マスタを編集したい」ではなく、**やりたいこと** で選んでください。

### 監査対策

- やりたいこと：運営指導で確認される内容を整えたい  
- 中身：監査項目の確認・編集  

### 加算設定

- やりたいこと：加算を正しく算定・説明できるようにしたい  
- 中身：加算カテゴリの項目管理  

### AI設定

- やりたいこと：AIの判定精度を上げたい  
- 中身への入口：
  - AI判定ルール  
  - 行政資料  
  - 法令・根拠  

### 法改正・行政情報

- やりたいこと：最新の行政情報に追従したい  
- 中身への入口：
  - 行政資料  
  - 法令・根拠  
  - 参照サイト  

### 運用サポート（左メニュー下部）

| メニュー | いつ使うか |
|----------|------------|
| 承認待ち | ルールを本番反映する前 |
| 更新履歴 | いつ誰が変えたか確認したいとき |
| 通知一覧 | 行政資料変更の通知状況 |
| ジョブ監視 | 自動同期の成功／失敗 |
| 自治体マスタ | 対応地域の追加・変更 |

## 8. 「利用可能」になったあとにやること

設定は「一度やって終わり」ではありません。次のタイミングでホームを見直してください。

| タイミング | 確認すること |
|------------|--------------|
| 週次・月次 | 「確認が必要なことがあります」が出ていないか |
| 加算を新規算定するとき | 加算設定・関連AIルール |
| 自治体の通知・法改正があったとき | 法改正・行政情報（資料・URL） |
| 指摘の質が低いと感じたとき | AI判定ルールの文言・対象書類 |
| 新しい自治体に展開するとき | 自治体マスタ → 監査項目 → AIルール |

**おすすめの習慣**

1. ホームを開く  
2. 状態が「利用可能」か見る  
3. 「次にやること」があればそれだけやる  
4. なければ日常の書類チェックへ戻る

## 9. よくあるつまずき

**Q. ルールを登録したのに「利用可能」にならない**  
A. **承認** まで終わっていますか。承認待ちが残っていると必須の「確認待ちを残さない」も未完了になります。

**Q. 必須は全部完了なのに、まだやることがあるように見える**  
A. 任意（加算・行政情報）が残っていると「次にやること」に任意が出ます。必須だけ見たい場合は、状態ラベルが「利用可能」かを確認してください。

**Q. 監査項目とAI判定ルールの違いは？**  
A. 監査項目＝「何を見るか」の見出し。AI判定ルール＝「どう見るか」の具体的な基準。両方そろって初めて安定します。

**Q. 行政資料と参照サイトの違いは？**  
A. 行政資料はPDFや自動監視の台帳。参照サイトは「どの公式URLを根拠にするか」の一覧です。まずは参照サイトだけでも構いません。

**Q. 設定を間違えたら現場のチェックが危険ですか？**  
A. 本サービスはWチェック支援であり、断定や合否保証はしません。それでも誤ったルールは混乱の元なので、変更は承認フローを通してください。

**Q. 誰がこの画面を使えますか？**  
A. 原則として **運営（サービス提供側のオペレータ）** 向けです。一般の事業所スタッフの日常画面とは分かれています。

## 10. 用語のやさしい説明

| 用語 | やさしい意味 |
|------|----------------|
| チェック設定 | AIチェックの「ものさし」を管理する一式 |
| 準備の進み具合 | 設定の完了度メーター |
| 必須 / 任意 | 始めに必要／あると精度が上がる |
| 利用可能 | 最低限そろって運用開始できる状態 |
| 監査項目 | 確認したいことの見出し |
| AI判定ルール | 見出しに対する具体的な見方 |
| 承認待ち | 本番反映前の確認キュー |
| ルールセット | 自治体×サービス種別のまとまり |
| 行政資料 | マニュアルPDFなどの台帳 |
| 参照サイト | 公式ページのURL一覧 |
| Wチェック支援 | 最終判断は人・施設が行う前提の補助 |
